# 普通去限购 + 秒杀限购下单实现方案

## Context（背景与目标）

商城 mall 门户（mall-portal）当前所有下单路径（普通结算 / 立即购买）都走同一套
`StockCacheService.deductStock` 的 Lua 预扣，并受全局配置 `purchase.limit-per-user`
限购约束，导致**普通商品购买也被限购**。

目标（用户明确要求）：
1. **普通购买不再限购**——普通 / 立即购买下单路径强制不限购。
2. **仅在「限时购 / 秒杀」场景限购**，限购数量为秒杀关系表配置的**固定值**
   `flashPromotionLimit`（商品自带，非全局动态）。
3. 秒杀库存复用普通 SKU 库存池（不拆分独立库存 key），仅新增限购约束。

现状关键点：
- 下单核心链路：`OmsPortalOrderService.generateOrder/generateBuyNowOrder`
  → `generateOrderWithLock`（Redisson 分布式锁 + 防重标记）
  → `generateOrderInternal`（交易内拼装订单 → Lua 预扣库存 → 异步 MQ 扣库存）。
- Lua 脚本 `stock_deduct.lua` 已原生支持「限购数 0 = 不限购」（`ARGV[2]`），复用于普通与秒杀。
- 秒杀配置：`SmsFlashPromotionProductRelation`（秒杀价 `flashPromotionPrice`、
  秒杀库存 `flashPromotionCount`、每人限购 `flashPromotionLimit`）。
- 秒杀活动/场次模型：`SmsFlashPromotion`（status/startDate/endDate）、
  `SmsFlashPromotionSession`（status/startTime/endTime），Mapper 均已存在。

## 改动设计

### 1. `StockCacheService`：库存预扣支持「维度化限购数」

放弃将全局 `limitPerUser` 直接用于普通下单，改为由调用方传入本次下单的限购数：

- 新增方法 `deductStock(Long memberId, Map<Long,Integer> skuQuantityMap, int limitPerUser)`。
- 原 `deductStock(Long, Map)` 保留，内部委托新方法并传 `limitPerUser = 0`（**不限购**），
  供普通 / 立即购买路径使用。
- `executeDeduct` 的 Lua `ARGV[2]` 值由字段 `limitPerUser` 改为方法参数传入的限购数。
- 全局字段 `limitPerUser`（`@Value("${purchase.limit-per-user:0}")`）保留不再被 ordinary 使用，
  仅构造时默认 0（可删除该字段，因普通路径已不依赖）。
- `releaseStock` / Lua `stock_release.lua` 无需改动（回补逻辑与限购数无关）。

### 2. 新增秒杀下单参数对象 `FlashPromotionOrderParam`

文件：`mall-portal/domain/FlashPromotionOrderParam.java`

- `extends BuyNowParam`（复用 `productSkuId`、`quantity` 及 `OrderParam` 的
  收货地址 / 支付方式等字段）。
- 新增字段：`flashPromotionId`、`sessionId`。

### 3. `OmsPortalOrderService` 接口新增「秒杀下单」

新增方法：
```java
Map<String, Object> generateFlashOrder(FlashPromotionOrderParam param);
```

### 4. `OmsPortalOrderServiceImpl`：实现秒杀下单

`generateOrderWithLock` / `generateOrderInternal` 需要把「订单类型 + 限购数」透传下去，
方案：分别为二者增加携带 `orderType` 与 `limitPerUser` 的内部重载，原签名委托默认值。

#### 4.1 改造参数透传
- `generateOrderInternal(..., boolean needDeleteCart, int orderType, int limitPerUser)`：
  库存预扣处调用 `deductStock(memberId, map, limitPerUser)`；
  订单类型赋值 `order.setOrderType(orderType)`。
- 新增内部入口 `generateFlashOrderInternal`（或复用 `generateOrderWithLock` 的重载），
  将 `orderType=1`、`limitPerUser=秒杀限购数` 传入。
- 普通 / 立即购买路径调用默认 `orderType=0`、`limitPerUser=0`（去限购）。

#### 4.2 `generateFlashOrder` 实现步骤
1. 参数校验：`flashPromotionId`、`sessionId`、`productSkuId`、`quantity>0`。
2. 校验活动与场次：
   - `SmsFlashPromotionMapper`：活动存在、`status==1`、当前日期 ∈ [startDate, endDate]。
   - `SmsFlashPromotionSessionMapper`：场次存在、`status==1`、当前时间 ∈ [startTime, endTime]。
3. 查询 `SmsFlashPromotionProductRelationMapper`（条件：`flashPromotionId + sessionId + productId`），
   校验存在，取 `flashPromotionPrice`（秒杀价）与 `flashPromotionLimit`（固定限购数）。
4. 组装秒杀 `CartPromotionItem`：
   - 价格 = `flashPromotionPrice`（覆盖原价，秒杀不叠加满减/优惠券/积分，`reduceAmount=0`、
     `promotionMessage="限时购"`、`integration/growth=0`）。
   - 库存 = SKU 可用库存（`stock - lockStock`，复用 `PmsSkuStockMapper`），用于 `hasStock` 与本地下单。
   - 设置 product/sku 相关元信息（参考 `getBuyNowCartPromotionItem`）。
5. 走「防重复下单 + 分布式锁 + Lua 预扣 + MQ 异步扣库存」的既有链路：
   `generateOrderWithLock`（或其秒杀重载），传 `orderType=1`、`limitPerUser=flashPromotionLimit`、
   `needDeleteCart=false`（秒杀不走购物车）。
6. 发货 / 取消 / 支付成功等后续逻辑全部复用现有实现（`orderType` 仅是订单标记）。

### 5. `OmsPortalOrderController` 新增秒杀下单接口

- `POST /order/generateFlashOrder`，入参 `FlashPromotionOrderParam`，
  调用 `portalOrderService.generateFlashOrder(...)`，返回 `CommonResult`。

### 6. 配置

- `application.yml` 中 `purchase.limit-per-user` 不再影响普通下单（保留默认 0）。
  如需可注释，但不强制删除。

## 涉及文件清单

- 修改：`StockCacheService.java`（deductStock 支持传入限购数）
- 修改：`OmsPortalOrderService.java`（新增 `generateFlashOrder` 接口）
- 修改：`OmsPortalOrderServiceImpl.java`（生成秒杀订单 + orderType/limitPerUser 透传）
- 修改：`OmsPortalOrderController.java`（新增 `/order/generateFlashOrder`）
- 新增：`FlashPromotionOrderParam.java`（秒杀下单参数）
- 复用不修改：`stock_deduct.lua`、`stock_release.lua`、`DistributedLockService`、
  RabbitMQ 库存扣减链路、秒杀活动/场次/关系 Mapper 与模型。

## 验证方式

1. 编译校验：
   `mvn -pl mall-portal -am compile -DskipTests`（surefire 60s 超时保护）。
2. 逻辑自查（无运行环境时）：
   - 普通下单 `generateOrder` / `generateBuyNowOrder` → `deductStock` 限购数传 0，
     确认 Lua ARGV[2]=0（不限购分支不会触发 `-3`）。
   - 秒杀下单 `generateFlashOrder` → 传 `flashPromotionLimit`，Lua ARGV[2]>0，
     超买返回 `-3` → `Asserts.fail("该商品每人限购X件")`。
3. 有运行环境时可结合 seckill 秒杀入口单测：同用户超过 `flashPromotionLimit` 秒杀购买被拒，
   普通商品任意数量购买不被限。
